# mfsi-cxr

**Distributional Cross-Modal Reliability and Verified Reasoning for Trustworthy Multimodal Chest X-Ray Diagnosis**

A research codebase for a master's thesis project at the Lebanese American University (MS Computer Science). It studies two questions on CheXpert Plus:

1. Can a label-free score tell us **which findings in a multimodal chest X-ray prediction should not be trusted**?
2. When those findings are sent to an LLM for a second opinion, does the LLM **actually use** the reliability signal, and do its stated reasons survive removal of the evidence they cite?

> **Status: research in progress.** This repository holds the implementation of a pre-registered study. No results are reported here until the experiments have been run. All numbers in the final report are generated by scripts from saved artifacts; none are written by hand.

---

## The idea in one minute

Most multimodal systems merge the image and the clinical text into one probability per finding. If the image says "present" and the text says "absent", that conflict disappears, and the clinician sees one confident answer.

This project keeps the two sources apart long enough to ask, for each of the 14 CheXpert findings: *how clearly does each modality separate this finding, and do the two modalities agree?*

| | Contribution | What it is |
|---|---|---|
| **C1** | **MFSI** (Multimodal Feature Separability Index) | A post-hoc, per-finding reliability score computed on frozen embeddings. It uses Mahalanobis distances to "present" and "absent" clouds in each modality, a hierarchical covariance shrinkage for rare findings, and a weakest-witness rule combined with a cross-modal agreement term. |
| **C2** | **Verified arbiter** | A local, open-weight LLM that reviews only the findings MFSI flags. Its answer passes a 3-run vote, a rule-based hierarchy check, and per-claim evidence removal. Each claim is tagged `VERIFIED` or `UNVERIFIED`. |

"Verified" means *the model used this evidence*, not *this is medically true*.

## Pipeline

```
 image(s) ──► DenseNet121 ─┐                                   ┌─► MFSI (post-hoc, frozen embeddings)
                           ├─► two-level gated-attention MIL ──┤        │
 report(s) ─► CXR-BERT ────┘   (images/reports → study → patient)       ▼
                                  │                          reliability R, flag, escalate?
                                  ▼                                     │
                      14 sigmoid outputs (flat head)                    ▼
                                                           evidence packet → local LLM
                                                                        │
                                                       3-run vote · hierarchy rule · evidence removal
                                                                        ▼
                                                      decision + claims tagged VERIFIED / UNVERIFIED
```

The classifier is trained first and then frozen. MFSI and the arbiter never change the diagnosis the classifier produces.

## Research questions and hypotheses

- **RQ1.** Does MFSI rank correct above incorrect predictions better than maximum softmax probability, ensemble variance, tied-covariance Mahalanobis, Euclidean distance, and local outlier factor? Does the two-modality version beat each single-modality version of itself (the decisive test)?
- **RQ2.** Do arbiter decisions change when reliability scores are shuffled across patients by more than they change when the same input is simply re-run? Do the arbiter's claims still hold when the evidence they cite is removed?

Failure is a valid result. If simple confidence is as good as MFSI, or the arbiter ignores the signal, that is reported as a finding.

## Data

**CheXpert Plus** (Stanford AIMI), distributed through Redivis: 223,462 image–report pairs from 64,725 patients, with the 14 CheXpert labels and RadGraph annotations.

- You must request access yourself and accept the data use agreement. **No data, report text, embeddings, or credentials are stored in this repository.**
- The full dataset is about 6.8 TB. Development starts with a **pilot subset** (default 3,000 patients).
- All splits are **by patient**, never by study.
- **Leakage rule.** Labels come from the Findings and Impression of a report. The text branch may read only the indication, history, technique and demographics of the index study; earlier studies' reports may be read in full. This is enforced by an allowlist loader and a canary test that must stay green.

## Getting started

Requirements: Python 3.11+, a CUDA GPU for training and for the local LLM, and approved CheXpert Plus access.

```bash
git clone <this-repo-url> mfsi-cxr
cd mfsi-cxr
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

pytest -q                       # runs on synthetic fixtures, no real data or GPU needed
```

Then set the data location in `configs/data.yaml` and run the steps in order. The planned order is:

```
10 audit → 11 index → 12 splits → 20 train → 21 extract → 22 probe
→ 30 / 31 MFSI fit and score → 40 / 41 RQ1 evaluation
→ 50 / 51 / 52 arbiter → 60 RQ2 evaluation → 99 make_report
```

`scripts/99_make_report.py` regenerates every table, figure, `REPORT.md` and `manifest.json` from the saved artifacts with one command. The test split is opened once, in the final evaluation scripts, after all configs and thresholds are frozen.

## Reproducibility and rules of the project

- Seeds are set everywhere; each run saves its config, git hash and package versions.
- Covariances are computed and inverted in float64 with Cholesky solves.
- Prototypes and covariances are fitted on **train only**. Temperatures and thresholds are tuned on **validation only**. The test split is never used for tuning.
- The arbiter LLM is **open-weight and run locally**. No patient-derived text is sent to a third-party API.
- Every cached LLM call is keyed by model, revision, prompt, seed and sampling settings, so reruns are deterministic.
- Patient data, report text, embeddings, caches and LLM logs are git-ignored and must never be committed.

## Ethics and data use

This project uses public, de-identified secondary data under a data use agreement. There are no human participants. The tool is a research prototype and **not a medical device**; it must not be used for clinical decisions. Whether verification tags protect clinicians from over-reliance on AI needs a human study and is outside the scope of this work.

## Use of AI tools

AI assistants were used to help prepare the proposal and to help write and review code under the rules in `CLAUDE.md`. The study itself uses AI components (the image and text encoders, and a local LLM as the arbiter). All uses are described in Section 9 of `docs/PROPOSAL.md`. All results come from scripts and saved artifacts, and the author is responsible for checking them.
